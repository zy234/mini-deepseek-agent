# byteseek/Mira

- 地址：https://github.com/byteseek/Mira
- 调研快照：约 262 Star，Apache-2.0，最近提交 2026-07-05
- 定位：带证据追踪和刷新能力的 Agent 原生投资研究工作区。

## 仓库实现方案

Mira 围绕 investment thesis 组织研究，覆盖股票、财报、宏观和组合复盘。核心思想是把一次性回答变成可以反复刷新、追加证据和修订结论的研究对象。

## 适合迁移的部分

- thesis 的状态：`draft`、`active`、`challenged`、`invalidated`、`archived`。
- 每条 thesis 绑定支持证据、反证、最后刷新时间和下次复查条件。
- 研究对象和聊天记录分离，便于第二天继续工作。
- 将新信息作为增量事件，而不是覆盖旧结论。

## 当前框架中的实现建议

复用 CLI 已有的会话持久化，再增加一个轻量 `research/` 目录和 Markdown frontmatter。每次 Agent 完成研究后写入 `thesis.md`，证据保存为 JSONL；下一次请求先读取摘要，再按用户要求刷新指定证据。

不要先引入数据库。用原子写入、唯一研究 ID、完整文件 hash 和日期字段保证可恢复性。`web_search` 只发现候选来源，`web_fetch` 只读取用户选定的页面。

## 许可证与风险

Apache-2.0 适合参考设计，但需要核对其依赖和数据源。可刷新不等于事实正确；每次刷新都应重新检查发布日期和来源是否仍可访问。

## 验证要求

测试重复刷新幂等、旧证据保留、证据失效标记、并发写入和文件被外部修改时的 hash 冲突。
